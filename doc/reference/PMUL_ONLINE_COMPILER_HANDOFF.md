# PMUL 在线因子模式：编译器交接

日期：2026-10-22。RTL 已实现；以下约定对应默认 `TWIDDLE_CHAINS=8`（K8）。

## 编码与语义

计算指令 opcode 仍为 **0x5B**，PMUL 的 `[31:28]=2`。

| 位 | 含义 |
|---|---|
| `[27:22]` | 目的对象 PDST，6 bit |
| `[21:16]` | 数据源对象 PSRC1，6 bit |
| `[15:14]` | I=0 时：00 原向量模式；**01 在线因子模式**；10/11 非法 |
| `[13:8]` | I=0 时：第二源对象；在线模式下指向两行参数对象 |
| `[7]` | I；在线模式必须为 0 |
| `[6:0]` | 0x5B |

**I=1 时 `[15:8]` 仍是完整 imm8**，包括 64、192、255，不能按模式位解释。PADD/PSUB/PMAC 的对象模式仍只接受 00。

在线模式执行 `dst[j] = src[j] * c * r^j mod q`，j=0…N−1；不执行 butterfly 或重排。q、Barrett 参数沿用 PMODLD；N 由源对象的实际行数乘 64 得到。允许 `dst=src`，也允许独立目的对象。

```c
uint32_t inst = (2u << 28) | (dst << 22) | (src << 16)
              | (1u << 14) | (param << 8) | 0x5Bu;
// 送入 HPU 的现有 26-bit command 为 inst >> 7。
// 例：dst=40、src=40、param=63，inst=0x2A287F5B。
```

DMA opcode 0x2B、rs1/rs2 位置均不变。无需新增 CPU 读寄存器操作；若核侧会检查或改写 PMUL 保留位，需要让 01 模式原样进入 HPU。

## 两行参数，固定 512 B

一行 256 B，64 个 little-endian uint32；所有值按普通模 q 剩余数存储，范围 `[0,q)`。先将全部 128 个 word 填 1，再设置下表字段。这里 **B=N/64**，与 NTT 的 N/128 不同。

| 位置 | 内容 |
|---|---|
| line 0，word ℓ=0…63 | `U[ℓ] = c * r^ℓ mod q` |
| line 1，word a−1，a=1…min(7,B−1) | `V[a] = r^(64*a) mod q`；V[0]=1 隐含 |
| line 1，word 7+t，t=0…T−1 | `R[t] = r^512 mod q`，`T=max(0,log2(B)−3)` |
| 其他 word | 1 |

每条指令重新从两行参数初始化内部状态。硬件交错执行因子递推和数据乘法，不改写参数对象；同一模板可重复使用。每条在线 PMUL 只读两行参数，增加的内部乘法复用现有 PE。

N=8192 时 B=128、T=4：line 1 的 word 0…6 放 V[1…7]，word 7…10 都放 `r^512 mod q`，word 11…63 为 1。

- pre：`c=1, r=ψ`，对应 `ψ^j`。
- post：`c=N^(-1) mod q, r=ψ^(-1) mod q`，对应 `N^(-1)*ψ^(-j)`。归一化已经包含在 U 中，不应再乘一次 N 的逆。
- 若当前流程最后只需统一乘 N 的逆，继续用原有标量/向量乘法安排；根据实际因子语义选择，避免重复归一化。

不要直接复用要求首元素为 1 的 NTT 参数校验：post 的 `U[0]=N^(-1)`。上述 R 的数量也要按 B=N/64 计算。

## 对象、容量与调度

- 数据长度必须是 2…1024 行的 2 次幂，即 N=128…65536。参数对象实际长度必须为 **2 行**，参数 ID 必须不同于 src、dst。对象 ID 范围仍为 0…63。
- 数据、参数和目的对象均不能使用模表对象。源和参数须已装载并有效；参数在指令完成前保持有效，之后可以复用或 PFREE。原有依赖检查负责等待在途操作。
- 推荐参数通过普通 DLOAD 装入 Bank 5：`MOD=0`、bank mask=`0x20`、长度 512 B；热参数可设 `CP=1`。参数也可在普通 bank，但会消耗普通分配块。模表仍使用原有 MOD/PMODLD 流程。
- 默认 Bank 5 共 32 行（8 KiB），模表保留 4 行（1 KiB），剩余 28 行最多放 **14 份**两行模板，NTT 与 pre/post 共用这些位置。10 份 pre/post 占 20 行（5 KiB），加模表后还剩 8 行，可放 4 份阶段模板；编译器需安排模板生命周期。
- 普通 Bank 0…4 仍各 1024 行，最小分配粒度仍为 128 行。N=8192 的多项式占 128 行，共最多 40 份；64 个逻辑 ID 不等于 64 份普通物理容量。独立目的对象也需要容量。
- 结果分配延续现有确定性策略。**镜像 allocator 的编译器需要特判本模式：持续读负载只计数据源，不把两行参数源计为逐组读负载**。原址结果仍保持原位置；新目的对象按现有冲突代价、空闲空间和确定性次序分配。

编译器最小改动：增加 PMUL 的在线模式编码和两行参数操作数类型；生成上述模板，替换完整 pre/post 向量的装载与乘法；更新功能模型及分配成本模型，按需复用模板。其他 PMUL 编码与同步方式保持原约定。

## 实现与验证

主设计位于 `rtl/cpu/SCPU_RTL/RTL/hpu/rtl/control/`，并同步到 `RTL/latest/` 中对应的 5 个模块。CPU、SoC 和 DMAC 设计未修改。

VCS RTL 回归已通过：131 次 PMUL 操作、1,437,184 个结果逐系数检查，NTT/INTT 共 82 个阶段，以及 64 对象管理回归。覆盖在线 pre/post、原址/独立目的、参数复用、背压、32 位模数、模数切换、非法编码/参数、在途复位，以及原向量/imm8 PMUL。结果见 [测试记录](../ver/it/core/Difftest/tests/pmul_online/results/20261022/results.json)。测试使用真实控制、PE、Barrett 与 SRAM RTL/宏模型；DMA 装载由测试台驱动，未跑 CPU/DMAC/NoC 整机 IT 或时序签核。
